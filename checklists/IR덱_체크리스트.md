# IR 덱 (Pitch Deck) 체크리스트

> 대상: Pre-Seed / Seed 라운드 투자 유치용 IR 덱
> 사용처: `templates/investment/IR_덱_템플릿_Seed.md` 로 작성한 덱의 출시 전 점검
> 참고: 상세 가이드와 슬라이드별 해설은 템플릿 파일 본문 참고

---

## 1. 슬라이드별 콘텐츠 체크

### 슬라이드 1. 표지 (Cover)
- [ ] 회사명·캐치프레이즈·발표자·날짜 명시
- [ ] 캐치프레이즈가 *10단어 이내* + *구체적* ("혁신적", "차세대" 같은 추상어 X)
- [ ] 발표 첫 문장이 표지와 자연스럽게 연결됨

### 슬라이드 2. One-Liner ⭐
- [ ] *타겟 / 기존 방식 / 새로운 방식 / 해결 문제* 4요소 포함
- [ ] 사업을 모르는 사람에게 보여줘도 *어떤 회사*인지 이해됨
- [ ] 핵심 숫자 3개 (트랙션·시장·임팩트) — *각 숫자에 출처 또는 근거*
- [ ] 표지 캐치프레이즈와 *깊이가 다른* 메시지

### 슬라이드 3. Problem
- [ ] *누가 / 언제 / 얼마나 자주* 고통받는지 명확
- [ ] 페인포인트가 *정량적* (시간·돈·기회손실)
- [ ] 문제 3개 이내로 압축
- [ ] *고객 인터뷰 인용구* 1개 포함 (실제 인터뷰 출처)
- [ ] 솔루션을 미리 설명하지 않음

### 슬라이드 4. Why Now
- [ ] *기술·규제·행동* 변화 중 2개 이상의 변곡점 제시
- [ ] *3년 전엔 불가능, 지금 가능* 시제 명확
- [ ] 각 변화에 *출처·근거 수치* 한 줄
- [ ] "AI가 대세니까" 같은 막연한 표현 없음

### 슬라이드 5. Solution
- [ ] *글*보다 *그림·스크린샷·데모*가 80% 면적
- [ ] 핵심 작동 원리 *3단계 이내*
- [ ] *고객이 얻는 가치* 중심 (기술 자랑 X)
- [ ] (가능 시) 30초 데모 영상 또는 GIF 삽입

### 슬라이드 6. Product (선택)
- [ ] *기능 차별점 + 구조적 차별점* 둘 다
- [ ] 비교표 *4열 × 5행 이내*
- [ ] Moat이 *시간이 갈수록 강해지는* 무엇인가
- [ ] *Solution이 단순하면 슬라이드 10(Competition)과 통합 검토*

### 슬라이드 7. Market Size
- [ ] TAM / SAM / SOM *세 숫자 모두* 제시
- [ ] *Bottom-up 계산식* 한 줄 포함 (가격 × 고객 수 × 침투율)
- [ ] 시장 성장률(CAGR) + 출처
- [ ] 모든 시장 숫자에 *출처 명시* (통계청, 업계 보고서 등)
- [ ] "1%만 가져와도 N억" 같은 표현 금지

### 슬라이드 8. Business Model
- [ ] 수익 모델 1~2개로 집중 (5개 이상 X)
- [ ] 가격 정책 *구체적 금액*
- [ ] Unit Economics 4지표 (CAC / LTV / LTV·CAC / Payback)
- [ ] *가정 기반*이면 *"가정"* 명시
- [ ] *고객·우리의 이해관계 정렬* 구조 보임

### 슬라이드 9. Traction
- [ ] *우상향 그래프* 1개 (또는 검증 신호 묶음)
- [ ] 지표 정의가 *명확* ("잠재고객 500" X / "결제까지 이어진 매장 12" O)
- [ ] *허영 지표(Vanity Metrics)* 없음
- [ ] 그래프 *Y축이 0에서 시작* (조작 없음)
- [ ] 트랙션 없으면 *검증 활동*(인터뷰·LOI·베타·대기자)으로 대체

### 슬라이드 10. Competition
- [ ] 2x2 포지셔닝 매트릭스 (축은 *고객 가치* 기준)
- [ ] *직접 경쟁 + 간접 경쟁 + 대체재* 모두 인정
- [ ] *"경쟁사 없습니다"* 표현 없음
- [ ] 차별점이 *기능 차이*만이 아닌 *구조적 차이* 포함
- [ ] *"왜 이 빈자리가 비어 있었는가"* 답 준비

### 슬라이드 11. Team ⭐⭐⭐
- [ ] *진짜* 사진 (일러스트·아바타 X)
- [ ] 각 팀원 *핵심 경력 1줄* (이력 나열 X)
- [ ] *Founder-Market Fit* 한 줄 명시 (왜 *이 팀*이 *이 문제*를?)
- [ ] 공동창업자 *강점이 보완* (전원 동일 직군 X)
- [ ] 풀타임·파트타임 *솔직* 명시
- [ ] 자문단은 *실제 기여* 있는 사람만

### 슬라이드 12. Roadmap
- [ ] 시간축 *명확* (3, 6, 12, 18개월)
- [ ] 마일스톤이 *측정 가능* ("열심히" X / "유료 매장 N개" O)
- [ ] *Series A 진입 조건*과 *직결*
- [ ] *현재 위치* (NOW) 라벨 명시
- [ ] 마일스톤이 *현재의 3~5배 수준* (10배 이상 X)

### 슬라이드 13. The Ask ⭐
- [ ] 금액 *큰 글자*로 슬라이드 상단·중앙
- [ ] 자금 사용 *4~5개 항목별 비율*
- [ ] 인력 채용 비중 *50~70%*
- [ ] *Bottom-up 역산* 가능 (인력 N명 × 인건비 × 기간)
- [ ] Runway *18~24개월* 명시
- [ ] *마일스톤이 슬라이드 12와 일치*
- [ ] Valuation 명시 여부 결정 (보통 *명시 안 함* 권장)

### 슬라이드 14. Vision
- [ ] *큰 그림 한 문장* (숫자 + 변화 동사 + 카테고리)
- [ ] *Call to Action* + 연락처 명시
- [ ] *표지와 수미상관* (시작-끝 호응)
- [ ] 마지막 발표 멘트 준비
- [ ] *"감사합니다 Q&A"* 단독 슬라이드 없음

## 2. 전체 흐름 (Narrative Flow)

- [ ] 14장 ± 2장 이내
- [ ] *기-승-전-결* 구조: 표지·One-Liner → Problem·Why Now·Solution → Market·BM·Traction·Competition → Team·Roadmap·Ask·Vision
- [ ] *각 슬라이드 사이 논리 다리* 점검 (다음 슬라이드가 *자연스럽게 예측*되나)
- [ ] 슬라이드 *제목만 읽어도* 덱 흐름이 파악됨
- [ ] 슬라이드 1장 = 메시지 1개 준수
- [ ] 같은 메시지 *3번 이상 반복* 없음

---

## 3. 디자인 (Visual Design)

- [ ] 16:9 비율
- [ ] 폰트 종류 *3개 이내*
- [ ] 색상 *주력 2~3종* 일관
- [ ] 한국어: Pretendard / Noto Sans KR / Spoqa Han Sans Neo 중 택1
- [ ] 헤드라인 28~36pt / 본문 16~20pt / 캡션 10~12pt
- [ ] 모든 슬라이드 *여백·그리드 일관성*
- [ ] 그래프·차트 *Y축 조작 없음*
- [ ] 로고·이미지 *해상도 충분* (인쇄·확대 가능)
- [ ] *흑백 출력해도 정보 전달*
- [ ] 페이지 번호 (송부용 권장)

---

## 4. 두 가지 버전 (발표용 vs 송부용)

### 발표용 (Pitch)
- [ ] 글자 최소화, 그림 중심
- [ ] 14장 ± 2장
- [ ] Speaker Notes에 *발표 스크립트* 별도 작성
- [ ] 키노트·PPT 등 *애니메이션 가능 포맷*

### 송부용 (Send)
- [ ] PDF 포맷
- [ ] *발표 스크립트가 슬라이드에 통합*되거나 *Speaker Notes 포함 출력*
- [ ] 부록(Appendix) 슬라이드 포함 (FAQ·재무 모델·기술 아키텍처)
- [ ] *One-Pager* 별도 작성
- [ ] 90초 이내 *데모 영상 링크*
- [ ] 파일명: `{회사명}_IR_Deck_v{버전}_{YYYYMMDD}.pdf`

---

## 5. 송부 (Sending)

- [ ] 이메일 본문 *3~5줄 요약* (덱 안 열어도 이해됨)
- [ ] *One-Pager PDF* 별도 첨부
- [ ] *데모 영상 링크* 공유
- [ ] 외부 공유 시 *DocSend·Notion 등 조회 추적 도구* 검토
- [ ] *워터마크 또는 공유 권한 제한*
- [ ] *오탈자 최소 3회 검토* (특히 *숫자 단위* — 천만/억)
- [ ] (가능 시) *공통 지인 통한 추천* 경로 확보

---

## 6. 발표 리허설 (Pitch Rehearsal)

### 시간 배분 (10분 피칭 기준)
- [ ] 슬라이드별 시간 측정 완료 — Team·Problem에 가장 많이, Roadmap·Ask는 짧게
- [ ] 총 *10분 ± 1분* 안에 마침

### 리허설 단계
- [ ] *혼자 거울 앞* 발표 (시간·말 막힘 점검)
- [ ] *팀 내부* 발표 3~5회
- [ ] *외부 시뮬레이션* 1~2회 (VC 출신·창업자 피드백)

### Q&A 단골 10개 답변 준비
- [ ] 왜 *이 문제*를 푸시는 건가요? (Founder-Market Fit)
- [ ] 고객 인터뷰 *몇 명*, *돈 내겠다는* 분 *몇 명*?
- [ ] *카카오·네이버* 같은 대기업이 출시하면?
- [ ] 왜 *지금* 이 사업인가요? (Why Now)
- [ ] 시장 규모 *계산 근거*는?
- [ ] LTV/CAC 가정의 *근거*는?
- [ ] 공동창업자 *지분 구조*는?
- [ ] 이미 *얼마·누가* 들어왔나요?
- [ ] Series A *언제·얼마* 계획?
- [ ] 이 사업이 *안 될 가장 큰 위험* 1가지?

### 답변 정렬
- [ ] 위 10개 답을 *공동창업자 셋이 동일하게* 정렬

### 현장 준비
- [ ] 데모 시연 환경 점검 (와이파이·화면 공유)
- [ ] *백업 PDF* USB·이메일에 별도 보관
- [ ] 도착 후 *발표 5분 전* 호흡 정리

## 8. 최종 출시 컷오프 (이 5개는 *반드시*)

덱 외에 *시간이 부족할 때* — 다음 5개만은 *반드시 통과*:

- [ ] **One-Liner (슬라이드 2)** 가 *친구에게 보여도 이해됨*
- [ ] **Team (슬라이드 11)** 에 *Founder-Market Fit 한 줄*
- [ ] **모든 숫자** 에 *근거·출처* 있음
- [ ] **Q&A 단골 10개** 답변 정렬
- [ ] **Roadmap ↔ The Ask** 의 *자금-마일스톤 논리 직결*

→ 위 5개가 *덱 신뢰도의 80%* 를 결정합니다.
