# 연구개발계획서 작성 팁

## 공통 원칙

### 1. 구체성이 생명
- "성능을 향상시킨다" (X)
- "응답 속도를 현재 500ms에서 100ms 이하로 80% 개선한다" (O)

### 2. 근거 기반 서술
- 주장에는 반드시 출처/데이터를 첨부
- "시장이 크다" → "국내 AI 시장 규모 25.5조원 (2025, IDC)"
- 가능하면 1차 데이터 활용 (직접 조사, 고객 인터뷰 등)

### 3. 논리적 흐름
```
문제 → 기존 한계 → 우리의 접근법 → 왜 가능한지 → 무엇을 달성하는지
```

### 4. 시각적 전달
- 복잡한 내용은 표, 그래프, 다이어그램으로
- 기술 아키텍처는 반드시 구성도 포함
- 일정은 간트 차트로 표현

## 유형별 팁

### 정부 R&D 과제

**핵심 평가 기준을 기억하세요:**
1. **필요성**: 왜 이 연구가 필요한가?
2. **우수성**: 연구 방법이 얼마나 우수한가?
3. **실현 가능성**: 정말 달성할 수 있는가?
4. **활용성**: 성과를 어떻게 활용할 것인가?

**자주 하는 실수:**
- 목표가 너무 크거나 모호함
- 연구 방법이 추상적 (구체적 알고리즘, 방법론 제시 필요)
- 기술 동향이 오래된 자료 기반
- 예산 산출 근거 부족
- 성과 목표가 비현실적

### 투자유치 사업계획서

**투자자가 보는 순서:**
1. 팀 → 2. 시장 → 3. 트랙션 → 4. 제품 → 5. 재무

**핵심 포인트:**
- **문제의 크기**가 곧 기회의 크기
- 트랙션이 가장 강력한 증거
- Unit Economics가 건전해야 함
- 팀의 도메인 전문성을 강조

**자주 하는 실수:**
- TAM을 너무 크게 잡음 (현실적 SOM이 중요)
- 경쟁사를 "없다"고 주장
- 재무 전망이 지나치게 낙관적
- 기술만 강조하고 사업 모델 약함

### 사내 R&D 기획

**경영진이 궁금한 것:**
1. 얼마 들고, 얼마 벌어다 주는가? (ROI)
2. 안 하면 어떻게 되는가? (리스크)
3. 언제 결과가 나오는가? (일정)

**핵심 포인트:**
- 회사 전략과의 정렬(alignment) 강조
- ROI를 보수적으로 제시
- 단계별 Go/No-Go 의사결정 포인트 명시
- 실패 시 손절 기준도 미리 정의
